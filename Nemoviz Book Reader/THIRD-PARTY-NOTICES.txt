NEMOVIZ BOOK READER — THIRD-PARTY COMPONENTS
============================================

NBR uses the components below. Each is used as a SEPARATE, DYNAMICALLY LOADED
library or as an unmodified package; none is statically linked into NBR itself,
and each can be replaced by the user with a compatible build. That is what the
LGPL asks for, and it is why NBR can be distributed under its own terms.

Last verified: 2026-08-07. Every licence named below was read out of the
component's own metadata or its own licence file on this machine; where that was
not possible the component is listed at the end as unestablished rather than
guessed at.


libmpv (mpv) — audio playback engine
------------------------------------
File     : libmpv-2.dll   (30.2 MB)
Build    : mpv-dev-x86_64-20260801-git-1d15686142
Built by : NBR, from gradic76/mpv-winbuild — a fork of zhongfly/mpv-winbuild
           carrying one patch, patch/0099-NBR-LGPL-audio-only.patch
Upstream : https://github.com/mpv-player/mpv
Licence  : LGPL v2.1 or later, mpv and FFmpeg alike.
           This file said "the FFmpeg it links is stated by the build to be
           LGPL v3" from 2026-07-30 until 2026-08-07. That WAS true, of the
           93.6 MB build we shipped then, which came from zhongfly and carried
           --enable-version3. It stopped being true the moment §10e' replaced it
           with our own 30.2 MB build, and the line was never updated. Checked
           three ways on 2026-08-07: patch/0099-NBR-LGPL-audio-only.patch, the
           patch our build actually applies, removes BOTH --enable-gpl and
           --enable-version3; --enable-version3 appears nowhere in the build log
           of the run that produced the shipped DLL; and the DLL itself carries
           no v3 marker.

AUDIO ONLY. This build decodes no picture of any kind — no video, no images, no
cover art (the Library shows format icons instead). FFmpeg is configured with
--disable-everything plus an enable-list derived MECHANICALLY from FFmpeg's own
classification: every decoder it marks as audio, every filter it marks A->A.
Nothing is hand-picked from what NBR happens to use today, so a book in a codec
nobody anticipated still plays, and the sound-processing work can reach for a
filter without needing another build.

mpv itself is built with every video, GPU and hardware-decode option disabled BY
NAME — all 48 of them. Leaving them at their default "auto" is not the same
thing: auto means "on if the dependency is present", the build image has those
dependencies, and mpv duly compiled D3D11 and VAAPI sources into an audio-only
build until they were each named.

Result: 93.6 MB -> 30.2 MB, a third of the size.

Verified on the shipped file, not on the artifact:
  - no libx264, libdvdnav/libdvdread, dvd://, cdda://, libx265, librubberband
    or libsmbclient. The one remaining "x264 - core" string is FFmpeg's H.264
    SEI parser reading a tag an encoder left behind — it is a reader, not an
    encoder, and the same string is in every LGPL build.
  - 214 of 214 audio decoders present, and NO video or image decoder at all,
    compared name by name against the enable-list.
  - 14 of 14 sample books: duration read, audio decoded, and the whole §8d
    filter chain accepted by the real C API.

IMPORTANT — this must stay an LGPL build. The ordinary Windows builds of libmpv
are GPL: they link libx264 and libdvdnav/libdvdread, which are GPL-2, and that
would make NBR's own distribution a GPL matter. NBR needs none of it — it plays
audio. Verified on this build by scanning the binary: no libx264 (the "x264 -
core" strings that remain are FFmpeg's H.264 SEI *parser*, reading the tag an
encoder left behind, and libx264/x264_encoder_open are absent), no libdvdnav,
libdvdread, dvd://, cdda://, libx265, librubberband or libsmbclient.

Reading fonts — five families for the reading window
------------------------------------------------------
Files    : embedded in the assembly; see Fonts\Licences\NOTICE.txt
Licences : SIL Open Font License 1.1 — Andika, Atkinson Hyperlegible Next,
           Lexend, OpenDyslexic
           Creative Commons Attribution 4.0 — Luciole
Texts    : Fonts\Licences\OFL-1.1.txt, Fonts\Licences\CC-BY-4.0.txt

Unlike the components above, these are not loaded as separate files: they are
carried inside the assembly and registered PRIVATELY, into the running process
only. Nothing is installed into Windows — NBR is portable, and a player run from
a stick should leave nothing behind on the machine.

None of the five is modified. That matters: an OFL Reserved Font Name binds only
a MODIFIED version, so shipping them byte for byte as published keeps those
clauses satisfied without a renaming exercise. Any future change to a font file
would put the Reserved Font Name back in play and needs a rename first.

Each copyright line in NOTICE.txt was read out of the font's own name table
rather than copied from a download page. That found one discrepancy worth
knowing about: OpenDyslexic's metadata says "All rights reserved" and gives no
licence URL, while its upstream repository ships OFL.txt covering exactly these
files. The metadata is stale; the licence is OFL 1.1.

FFmpeg IS LGPL v2.1 - AND THE ROAD TO FINDING OUT IS WORTH KEEPING
-------------------------------------------------------------------
Settled 2026-08-07, after being got wrong first.

THE WRONG ANSWER, and why it looked right. gradic76/mpv-winbuild carries TWO
patches that both configure FFmpeg. compile-lgpl-libmpv.patch is zhongfly's
upstream one: it removes --enable-gpl and KEEPS --enable-version3. Reading it
gives "FFmpeg is LGPL v3", confidently and wrongly - because NBR's build does
not apply that file at all. It is reached only when a run is dispatched with
lgpl=true, and the run that produced the shipped DLL was dispatched lgpl=false.

THE RIGHT ANSWER. What NBR's build applies is
patch/0099-NBR-LGPL-audio-only.patch, in the ordinary patch loop, and that one
removes --enable-gpl AND --enable-version3. Three independent checks agree:
  - the patch itself: both flags are removal lines;
  - the build log of the run that produced the shipped DLL: --enable-version3
    appears nowhere in 3067 lines, while "Applying: NBR: LGPL, audio only" does;
  - the DLL: no v3 marker, and no version string at all. (The twenty "GPL" byte
    sequences a plain search finds are machine code - H?GPL, L?GPL and the like;
    the one real "LGPL" string belongs to libssh.)

So FFmpeg here has been LGPL v2.1 since 10e' replaced the 93.6 MB zhongfly build
with our own 30.2 MB one. The "LGPL v3" line this file carried was true of the
build it was written for, and was simply never updated.

WHAT IT COSTS: nothing, which is the point. No rebuild is needed, the MSIX
relink wrinkle never applied to the DLL we actually ship, and LGPL-3.0.txt and
GPL-3.0.txt - added on 2026-08-07 and removed the same day - covered nothing.

THE LESSON, since this file is where it will be re-read: two patches in one
repository can both look authoritative, and the one that is NOT applied reads
exactly like the one that is. Check what the BUILD did, not what a patch says.

STILL TO RESOLVE BEFORE ANY RELEASE
-----------------------------------
Nothing on the licence side, as of 2026-08-07. Every component the project
references is named above, every licence was read from that component's own
metadata or its own licence file, and every text ships.

Nothing on the packaging side either, which was the last thing thought to be
open: FFmpeg is already LGPL v2.1, so no installer has to make libmpv-2.dll
replaceable on its account.

Two things that are NOT licence questions but touch this file:
  - a fork run dispatched with lgpl=true fails, and always would have:
    compile-lgpl-libmpv.patch conflicts with patch/0099-NBR-LGPL-audio-only.patch
    because they configure the same two files. Build with lgpl=FALSE, as every
    working build has.
  - the fork's own patches for libpsl, curl, c-ares and mpv-enable-libcurl no
    longer apply cleanly against upstream. They fail tolerated (the loop ends in
    "|| git am --abort") so the build still succeeds without them, but that drift
    will widen.
